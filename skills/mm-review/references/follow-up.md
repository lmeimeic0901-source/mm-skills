# 局部复改与收稿

日期：2026-10-03  
对应版本：meimei-draft-review v1.3.0

本规则用于已交付方向单或成稿之后，收到学员反馈或局部方案选择时。适用于广告和日常笔记；不把后续对话自动当成新一次全篇重写。

## 〇、不能忘记前面（最优先）

- 每一轮都以上一轮交付的“当前版本”为底稿，不回到原稿重新改，也不凭印象重写。
- 学员明确说满意的段落（“开头可以”“这段挺好”“就这样”）记为已锁住，之后每一轮逐字保留，除非她本人要求改这一段。
- 没被点名的段落逐字照抄上一版，包括标点。为了衔接确实要动前后一两句时，在交付里说明动了哪句、为什么。
- 学员说“删掉这段”“这句不要”，只删她点名的部分；删完补必要衔接，不顺手重写其他段。
- 交付前把新版和上一版逐段比对，确认除了点名的段落和说明过的衔接句，其他一字不差。

## 〇之二、学员不同意第一轮的判断

- 学员说“我觉得挺好”“这句没问题吧”，没给新事实：判断不变，引原句用一句话重说依据（谁看到会怎样），再问要不要按这个改。不因为学员不同意就把问题说轻或撤回。
- 学员补了新事实（Brief 要求、真实情况、写给谁）：按新事实重判，说明改了哪一条、为什么。
- 改稿过程中不回头改第一轮的判断，不为了让方向好写而改判断。
- 学员回“按推荐的改”：照推荐改法的段落顺序写完整稿，方案里写“顺序不动”的段原样放进当前版本，对照表只列改了的段。
- 学员调整了某几段（“第 2 段别动”“开头用方向二的”）：按她说的改方案，直接出完整稿，不再交一遍方案。
- 学员选了其他方向：按那个方向出完整稿，判断不变。

## 〇之四、学员回“查卡审”

按 [升维审稿](review.md) 第三节认真查两类，最多 3 条，只提示不改稿；没有就说“这两类说法没有，可以放心发”。查完回到原来的进度：没出成稿的继续等她选，出了成稿的不重贴全文。

## 〇之三、学员觉得“还不够好”

先用一两句肯定现在这样改的原因和思路（为什么这么排、保住了什么），再按她说的走：

- 只说“还不够好”“还能更好吗”，没说哪里：请她指出位置——开头、哪一段，还是结尾。她已经说了位置就不再问。
- 指出了位置，没说怎么改：只针对那个位置，给一两个和整篇逻辑接得上的备选，每个一两句；她选了再出整篇。不重审全篇，不推翻第一轮的判断。
- 想大改，但没说怎么改：坚持判断，充分讲清楚——这篇好在哪、大改会丢掉什么、刷到的人会怎么想。不因为她不满意就把判断说轻。
- 自己给了明确改法（“开头我想换成夏天5个巨好用的神器”）：按她的思路改一版，和推荐版放在一起，只对比改了的那部分，各写一句刷到的人会怎么想；说实话，但用哪个由她定，她选了再出整篇。

## 一、先找本轮要改什么

从对话取得：最近交付的整稿、学员明确认可的部分、待改句段、具体不满及新提供的事实或品牌要求。只在内部维持这些信息，不要求学员填表或逐段打勾。

- 学员说“开头可以，产品那段别扭”：开头是明确认可，产品段是本轮范围；其他段落暂时保持原样，不称为已认可。
- 学员只说“改这句”：本轮以最近交付版本为基础，只改这句及确实受影响的前后句。不再让学员确认剩余全文。
- 学员说“这块不自然”且上文能定位：先用一句话说明理解的地方，再给改法。位置或期望不明且可能改错时，只问一个具体问题，例如“你指的是产品出现得突然，还是介绍产品的这几句不像你平时说的话？”
- 学员说“都行，你决定”：可以采用推荐方案，不再增加一轮选择。
- 学员只说“收到”：不视为选定某个备选，不继续改稿，也不要求补一遍认可清单。
- 学员发回替换「【可以这样加】」的自己经历：用她的经历替换补充段，保留她说的细节和口气，去掉标记，和前后句连读检查；她的经历和补充写法不同时，以她的为准。她说“就用你写的”时，去掉标记，按通用做法的口吻写，不改成她的亲历。
- 学员补的料比预想的有料（例如一个很有画面的细节、一句很有劲的原话、一个意外的结果）：除了替换对应段落，可以把它用到开头、重点段或结尾这些最显眼的位置（例如结尾回扣这句话），连带调整受影响的前后句；交付时列清这次改了哪几处、为什么，没提到的段落不动。

“有依据”指 Agent 讲清楚改动的原因，不是要求学员证明不满意。学员的口吻偏好、试读感受、真实经历纠正都是有效输入。指出具体观察，例如“前一段还在讲挑选方法，下一段马上罗列三个卖点，缺了你为什么选这瓶的一句”，不把“更高级、更自然”当完整理由。

## 二、什么时候直接改，什么时候给方案

学员指出了问题、方向也清楚（“开头太长”“太刻意”“这句不喜欢”“说错了”“删掉”），直接改好，只给改动部分，不给选项。只有要新写法、又没说往哪边（“开头再换换”“都不好”“没感觉”），才给 2—3 个局部改法。学员说了自己的想法，以她的想法为主线写，不换成别的方向，最多附一句小建议。

每个方案包含：

1. 一个易懂的名字，说明实际区别，例如“顺着挑选标准说”“先说实际用着怎样”。
2. 可以直接使用的完整句子或局部段落。
3. 一句说明为什么这样改，以及与前后文如何相连。

明确推荐一个，说清它为什么更适合当前稿；不把所有方案写成“各有优势”。方案之间要有实质区别，不能仅换同义词。多个反馈尽量集中处理；不对每个小问题展开三个方案造成大量组合选择。

如果已有三列对照需求，将“当前句段｜局部改法 A/B｜差别与推荐理由”放入局部三列对照；不要再次铺开整篇原稿。

事实写错、品牌要求补漏、用户已指定改法、要求直接改或直接出完整稿时，直接完成修改并解释，不强迫先选方案。关键事实缺失且会决定改法时先问清，不生成建立在不同虚构经历上的备选。

若新要求会明显削弱已经解决的问题，点明影响并提出较小的改法。例如“把全部掉发原因加回去，会让半年洗护经历又拖到后面。建议只补与你挑洗发水有关的这一句。”尊重风格偏好，不以模型个人偏好阻止作者选择。

## 三、选定后整合

用户选定方案、明确采用推荐或给出确切修改要求后：

1. 以最近交付版本及已选修改为基础，只替换本轮涉及的位置。
2. 把修改段落与前后相邻段连读；必要时做最小衔接调整并说明，不能仅因局部改动就换开头、改卖点或改结尾。
3. 输出完整修改段落，简短说这次解决了哪个问题。不要只散列替换词，让学员自行拼接。
4. 只展示改动的段落：改前、改后和一句说明（“这次只改了第 X 段，其他段落和上一版一字不差”），不重贴全文，学员手里有稿。学员要看全文、要定稿时，才给新的“当前版本”全文；改动多也只列改动的段落。内部仍以合并后的整篇为下一轮底稿。不重做首轮长审核。
5. 若未选定多个互斥备选，不擅自拼接。可以明确给出推荐稿，但标明尚待选择，不写成学员已确认。

## 四、决定继续还是收稿

| 当前情况 | 本轮结尾 |
| --- | --- |
| 指出的具体问题已经解决，未发现关键缺口或新问题 | 简短总结后明确“建议用这一版定稿”，不再自动生成备选或笼统问是否继续优化。 |
| 尚有一个具体问题影响完整稿 | 指出具体句段、影响和下一步改法；能直接解决就本轮解决，必须由学员决定或补事实的才追问。 |
| 两个说法都合理，学员还没选 | 推荐一个并说明区别，只请选择当前局部方案；不再次邀请全篇重新反馈。 |
| 问题已解决，只想不断换同义说法 | 说明当前未发现新的具体问题，推荐保留当前稿，先连着试读；如果有明确不顺口的位置，再针对该位置处理。 |
| 新增真实经历、品牌要求或纠正 Agent 的错误 | 修正受影响部分；不以“已定稿”或“次数用完”为由拒绝。 |
| 学员想换整个创意、换主要受众，或把推荐产品改成分享经验等 | 用学员听得懂的具体要求说明整条稿的哪些地方会变，另出版本比较。不得套用“换内容目标”作含糊解释。 |
| 关键资料仍缺少 | 给已完成局部及最小待确认问题，明确为待确认稿，不假装已定稿。 |

默认按“一次集中反馈 → 局部方案或直接修正 → 整合收稿”组织，不设机械拒绝后续纠错的上限。不得承诺定稿必爆、必涨粉、必转化或必过品牌。

沉默不是认可。学员没有反馈时停止主动修改；学员明确说没有问题、采用此稿或选择方案时，才记录对应的认可状态。推荐定稿表示 Agent 的编辑判断，不表示品牌已通过或学员已确认。

## 五、可用的简短收尾

### 方向单之后

你选一个方向，或者说想往哪边走，我按它写全文。

### 成稿交付后

哪句不顺、哪里不对，发我那句，其他段落不动。没有要改的，这版就可以拍了。

### 给出局部方案后

我更推荐 A，因为它能顺着前面的挑选方法讲到这瓶产品。你可以选 A 或 B，选定后我把这一段和前后句整理好。

这是结构示例，实际推荐必须与本稿问题一致，不能照搬选择理由。

### 局部修改完成后

这一段已经按你选的写法改好，前后也顺过了。这次解决了［具体问题］，建议用这一版定稿，本轮先到这里。

方括号必须替换为本稿具体问题，不能出现在实际交付。关键问题尚未解决时，不能使用这句收尾。

### 不建议继续换说法时

目前这段已经把［具体意思］讲清楚，也能顺着前后文读下来，暂时没有发现需要再改的地方。建议先保留这一版，连着读一遍，看看实际说起来是否顺口。

### 想换整个写法时

如果你想把这条改成［具体新要求］，开头和后面的安排也需要一起调整。我会另出一版，保留当前稿，方便比较。

以上话术用于表达具体状态，不每轮全部展示，不反复邀请无范围的优化。
